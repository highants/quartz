# Quartz v4からv5へのバージョンアップ手順マニュアル（GitHub Pages対応版）

> [!SUMMARY] 情報参照元
> - [Migrating to Quartz 5 | Quartz 5](https://quartz.jzhao.xyz/getting-started/migrating)
> - [Hosting - GitHub Pages | Quartz 5](https://quartz.jzhao.xyz/hosting#github-pages)
> - [ThemesCore | Quartz 5](https://quartz.jzhao.xyz/plugins/themescore)

## v4からの主な変更点

| 項目 | v4 | v5 |
| :--- | :--- | :--- |
| **設定ファイル** | `quartz.config.ts` / `quartz.layout.ts` | `quartz.config.yaml` に統合 |
| **プラグイン管理** | 組み込み中心 | 外部化（ビルド前に `npx quartz plugin install` が必要） |
| **使用ブランチ** | `v4` | `v5`（新規ブランチへ移行し、デフォルトブランチを切り替え） |
| **URL形式** | 大文字・小文字混在 | 小文字・ハイフン区切りへ自動変換（旧URLは `AliasRedirects` がリダイレクト） |

---

## Step 1. コンテンツのバックアップ

ブランチを切り替えると作業フォルダ内のファイルが v5 の構成へ置き換わるため、事前に記事データ（`content` フォルダ）をリポジトリ外の安全な場所へコピーする。

- **手動コピーの場合:** エクスプローラー等で `content` フォルダを Quartz フォルダ外の任意の場所へコピーする。
- **コマンドで行う場合（Windows PowerShell）:**
  ```powershell
  Copy-Item -Recurse content $env:TEMP\quartz-content
  ```
  ※ `$env:TEMP` は Windows の一時フォルダを指す。

---

## Step 2. v5ブランチの取得と初期セットアップ

ローカルの Quartz ルートフォルダでターミナルを開き、本家リポジトリから `v5` ブランチを取得する。

```bash
# 本家リポジトリを upstream として登録（すでに登録済みのエラーが出た場合は無視して次へ）
git remote add upstream https://github.com/jackyzha0/quartz.git

# v5 ブランチを取得してローカルブランチを作成
git fetch upstream v5
git checkout -b v5 upstream/v5

# 依存パッケージのインストールとリモートへのプッシュ
npm i
git push -u origin v5
```

続いて、セットアップウィザードを実行して基本設定とコンテンツの復元を行う。

```bash
npx quartz create
```

- **テンプレート選択:** 用途に合うもの（Obsidian Vault の場合は `obsidian` など）を選択する。
- **コンテンツ復元:** ウィザードで「コピー」を選んでバックアップ先を指定するか、完了後に手動でバックアップを新しい `content/` フォルダへ戻す。

## Step 3. ローカル動作確認とテーマ設定の調整

デプロイ前にローカル環境でビルドできるか確認する。

```bash
npx quartz build --serve
```

ブラウザで `http://localhost:8080` を開き、記事やレイアウトが正しく表示されることを確認できたら `Ctrl + C` で終了する。

> [!WARNING] つまずきポイント①：テーマ読み込みの致命的エラーが出る場合
> `Error: Cannot find module '@quartz-themes/default'` のようなエラーで停止する場合は、`quartz.config.yaml` 内の ThemesCore（`@quartz-themes/core`）設定が原因。
>
> - **標準テーマを使う場合:** `quartz.config.yaml` で該当プラグインを `enabled: false` に変更（またはブロックを削除）する。
> - **Obsidian コミュニティテーマを使う場合:** `theme:` に実在するテーマ名を指定し、必要に応じて `npx quartz plugin install` を実行する。
>   ```yaml
>   - source: "@quartz-themes/core"
>     enabled: true
>     options:
>       theme: Tokyo Night # Minimal や AnuPpuccin など任意のテーマ名
>       mode: both
>   ```

## Step 4. GitHub Pages用デプロイ設定の作成

`.github/workflows/` フォルダ内に、**`deploy.yml`** という名前で新しいワークフローファイルを作成する。

> [!CAUTION] つまずきポイント②：既存の `deploy-v5.yaml` との混同に注意
> v5 ブランチに最初から入っている `.github/workflows/deploy-v5.yaml` は、本家開発者（`jackyzha0/quartz`）の Cloudflare Pages 用ファイルであり、個人のリポジトリでは動作しない。必ず GitHub Pages 用の `deploy.yml` を別途作成する。

**`.github/workflows/deploy.yml` の記述例:**

```yaml
name: Deploy Quartz site to GitHub Pages

on:
  push:
    branches:
      - v5
  workflow_dispatch:

permissions:
  contents: read
  pages: write
  id-token: write

concurrency:
  group: "pages"
  cancel-in-progress: false

jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v6
        with:
          fetch-depth: 0 # Git履歴のタイムスタンプ取得用
      - uses: actions/setup-node@v6
        with:
          node-version: 24
      - name: Cache dependencies
        uses: actions/cache@v5
        with:
          path: ~/.npm
          key: ${{ runner.os }}-node-${{ hashFiles('**/package-lock.json') }}
          restore-keys: |
            ${{ runner.os }}-node-
      - name: Cache Quartz plugins
        uses: actions/cache@v5
        with:
          path: .quartz/plugins
          key: ${{ runner.os }}-plugins-${{ hashFiles('quartz.lock.json') }}
          restore-keys: |
            ${{ runner.os }}-plugins-
      - name: Install Dependencies
        run: npm ci
      - name: Install Quartz plugins
        run: npx quartz plugin install
      - name: Build Quartz
        run: npx quartz build
      - name: Upload artifact
        uses: actions/upload-pages-artifact@v3
        with:
          path: public

  deploy:
    needs: build
    environment:
      name: github-pages
      url: ${{ steps.deployment.outputs.page_url }}
    runs-on: ubuntu-latest
    steps:
      - name: Deploy to GitHub Pages
        id: deployment
        uses: actions/deploy-pages@v4
```

あわせて GitHub リポジトリの **Settings → Pages** を開き、**Build and deployment > Source** が **`GitHub Actions`** になっていることを確認する。

## Step 5. GitHubへの同期とデプロイ実行

変更をコミットして GitHub へプッシュする。

```bash
npx quartz sync
```

プッシュ後、GitHub リポジトリの **Actions** タブでワークフローの実行状況を確認する。

> [!WARNING] つまずきポイント③：`build` は成功するのに `deploy` だけ失敗する
> `Branch "v5" is not allowed to deploy to github-pages due to environment protection rules.` というエラーが出る場合、v4 時代に作成された `github-pages` 環境が古いブランチのみを許可する設定のままになっている。
>
> **対処手順:**
> 1. GitHub リポジトリの **Settings → Environments** を開く。
> 2. `github-pages` の右端にある **ゴミ箱アイコン** をクリックして削除する（※削除時に2段階認証の6桁コード入力またはメール認証が求められる）。
> 3. **Actions** タブに戻り、失敗したワークフローの右上から **Re-run jobs → Re-run failed jobs** を実行する。
> 4. `github-pages` 環境が `v5` 用に自動再作成され、デプロイが完了する。

> [!NOTE] GitHub上に表示されるプルリクエスト通知について
> - `v5` ブランチへのプッシュ直後に表示される **「Compare & pull request」** の黄色いバーは、`v4` へ合流させる必要はないため無視して問題ない。
> - v4 時代に Dependabot が自動作成した古いプルリクエストが残っている場合も、不要であれば無視または Close して大丈夫。

## Step 6. 公開確認とデフォルトブランチの切り替え

1. **公開サイトの確認:**
   Actions のステータスが緑色（Success）になったら、公開 URL にアクセスして記事・テーマ・リンクが正しく表示されることを確認する。
2. **デフォルトブランチの切り替え:**
   - GitHub リポジトリの **Settings → General** を開く。
   - **Default branch** 欄の切り替えアイコン（左右の矢印）をクリックし、**`v5`** を選択して **Update** を押す。

---

## 移行後の運用メモ

- **記事の更新と公開:** 普段通り `content/` 内を編集したあと、`npx quartz sync` を実行するだけで自動的にビルド・デプロイされる。
- **プラグインの追加・管理:** プラグイン構成を変更した場合は、ローカルで `npx quartz plugin install` を実行して `quartz.lock.json` を最新状態に保ってから同期すると、GitHub Actions 側のビルドも安定する。
